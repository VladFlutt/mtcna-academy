# Lesson: Port knocking

> Этот модуль идёт по слайдам курса MTCSE, глава 5 «Security Router».

### Что такое port knocking

**Port knocking** («стук в порты») это способ **открывать порты на файрволе извне**, генерируя **попытки подключения к набору заранее заданных закрытых портов**. Когда получена правильная последовательность попыток, правила файрвола **динамически изменяются**, и хосту, который «стучал», разрешается подключаться к определённым портам.

«Стук» может состоять из любого количества пакетов **TCP, UDP и даже ICMP и других протоколов** на пронумерованные порты устройства. Порты для стука остаются **закрытыми**: никто не отвечает, сканер ничего не видит.

Представьте секретный стук в дверь: дверь заперта и молчит, но если постучать *три, потом два, потом один*, её откроют, только для вас.

### Как это сделать в RouterOS

Отдельной функции «knock» нет. Её собирают из **списков адресов с таймаутами**:

1. Пакет на первый порт помещает источник в список **knock1** на короткое время.
2. Пакет на второй порт, **только от источника, уже находящегося в knock1**, помещает его в **knock2**.
3. Пакет на третий порт от источника из knock2 помещает его в **knock-final** на долгое время.
4. Защищаемый сервис отбрасывается для всех источников, **не** находящихся в knock-final.

### Правила со слайда

    /ip firewall filter
    add action=add-src-to-address-list address-list=knock1 address-list-timeout=10s \
        chain=input dst-port=11111 protocol=tcp
    add action=add-src-to-address-list address-list=knock2 address-list-timeout=10s \
        chain=input dst-port=22222 protocol=tcp src-address-list=knock1
    add action=add-src-to-address-list address-list=knock-final address-list-timeout=1d \
        chain=input dst-port=33333 protocol=tcp src-address-list=knock2
    add action=drop chain=input dst-port=8291 protocol=tcp src-address-list=!knock-final

![Правила port knocking со слайдов (слайд курса)](/img/mtcse/se5-04.webp)

`!` в `src-address-list=!knock-final` означает **НЕ**: правило срабатывает для источников, которых **нет** в списке.

### Проследим стук пошагово

| Время | Клиент отправляет | Списки после пакета | Winbox? |
|---|---|---|---|
| 0 с | TCP на 11111 | knock1 (истекает на 10 с) | Отброшен |
| 3 с | TCP на 22222 | knock1, knock2 (истекает на 13 с) | Отброшен |
| 5 с | TCP на 33333 | knock1, knock2, **knock-final (1 день)** | Отброшен |
| 6 с | TCP на 8291 | knock-final | **Принят** |

И три способа ошибиться:

- **Слишком медленно**: стук в 11111, ждём 15 с, потом 22222 и 33333. knock1 уже истёк, поэтому 22222 не добавляет источник в knock2, и 33333 тоже ничего не делает. Winbox остаётся закрытым.
- **Неверный порядок** (33333, 22222, 11111): правилу 33333 нужен knock2, правилу 22222 нужен knock1. Ничего не открывается.
- **Пропущенный стук** (11111, 33333): 33333 требует knock2, до которого источник не дошёл.

### Клиенты для стука

Подойдёт любой инструмент, отправляющий пакет на порт (даже браузер или telnet). На слайдах:

- **Linux**: установка `apt-get install knockd` (в пакете есть клиент `knock`).
- Использование: `knock host 12345:tcp 54321:udp`. Отправляет TCP на 12345, затем UDP на 54321.
- Для Windows и Android тоже есть приложения.

Пример для наших правил:

    knock 22.1.1.33 11111 22222 33333
    # теперь в течение суток подключайтесь Winbox к 22.1.1.33

### Слабые места

Port knocking это **дополнительный слой**, а не замена паролей и шифрования. Стук передаётся открыто: тот, кто может **перехватить** ваш трафик, увидит последовательность и **повторит** её. Сочетайте его с ограничением сервисов, сильными пользователями и защитой от перебора.

### Лаба со слайда

> **Лаба:** *Откройте доступ к Winbox с помощью port knocking. Создайте правила в новой цепочке. Убедитесь, что защита от перебора паролей продолжает работать.*

Пошагово:

1. Создайте три правила стука в цепочке **knock**, а не в input.
2. В input добавьте `action=jump jump-target=knock` (для TCP) **перед** финальным drop.
3. Добавьте правило drop для TCP 8291 от источников, **не** входящих в knock-final.
4. Оставьте правила защиты SSH от перебора из модуля 3 рабочими.

    /ip firewall filter
    add chain=knock protocol=tcp dst-port=11111 action=add-src-to-address-list \
        address-list=knock1 address-list-timeout=10s
    add chain=knock protocol=tcp dst-port=22222 src-address-list=knock1 \
        action=add-src-to-address-list address-list=knock2 address-list-timeout=10s
    add chain=knock protocol=tcp dst-port=33333 src-address-list=knock2 \
        action=add-src-to-address-list address-list=knock-final address-list-timeout=1d
    add chain=input protocol=tcp action=jump jump-target=knock place-before=0
    add chain=input protocol=tcp dst-port=8291 src-address-list=!knock-final action=drop place-before=1

Пакеты на 11111, 22222 и 33333 всё равно отбрасываются в конце input: стуку нужно только **дойти** до маршрутизатора, ответ не нужен.

Попробуйте в **Симуляторе port knocking** и в лабе **«Доступ к Winbox через port knocking»**.

# Lesson: Порты сервисов по умолчанию

### Номера портов

- Порт это 16-битное число: **0-65535**.
- Их назначает **IANA** (Internet Assigned Numbers Authority). Старый список был опубликован в **RFC 1700**.
- **0-1023**: **известные порты (well-known)** (системные сервисы: 22 SSH, 80 HTTP, 443 HTTPS...).
- 1024-49151: зарегистрированные порты; 49152-65535: динамические (клиентские).

### Сервисы RouterOS и их порты по умолчанию

| Сервис | Порт по умолчанию |
|---|---|
| telnet | 23 |
| ftp | 21 |
| www | 80 |
| ssh | 22 |
| www-ssl | 443 |
| api | 8728 |
| winbox | 8291 |
| api-ssl | 8729 |

Боты сканируют прежде всего именно эти порты. Перенос сервиса на необычный порт не делает его защищённым, но убирает из логов большую часть автоматического шума.

### Конфигурация со слайда

    /ip service
    set telnet disabled=yes
    set ftp disabled=yes
    set www port=8800
    set ssh port=22000
    set api disabled=yes
    set www-ssl certificate=webfig disabled=no port=44300
    set winbox port=58291

После этого:

- к **ssh** подключаются так: `ssh -p 22000 admin@router`;
- к **Winbox** по адресу `router:58291`;
- к **WebFig** через `http://router:8800` или `https://router:44300`.

**www-ssl** нужен сертификат. Для быстрого теста создайте и подпишите его сами:

    /certificate add name=webfig common-name=192.168.33.1 key-usage=tls-server
    /certificate sign webfig

> Последняя строка слайда: **«also use firewall rules»** (используйте также правила файрвола). Изменённый порт находится полным сканированием за минуты. Ограничьте сервисы через `address=` и отбрасывайте управление из WAN в цепочке input.

Практика в лабе **«Перенос сервисов с портов по умолчанию»**.

# Lesson: SSH-туннели

### Что это

**SSH-туннель** (проброс портов) переносит другие TCP-соединения **внутри зашифрованной SSH-сессии**. На слайдах это описано как способ *инкапсулировать незашифрованный трафик и передать его через зашифрованный канал*. Типичная задача: добраться до сервиса, **не открытого в Интернет** (WebFig, база данных, Winbox), когда открыт только SSH.

### Локальный проброс: ssh -L

    ssh -L 9999:localhost:5432 host2

Читаем слева направо:

1. **9999**: ваш компьютер начинает слушать локальный порт 9999.
2. **host2**: вы открываете SSH-сессию к host2.
3. **localhost:5432**: соединения на ваш локальный 9999 передаются через SSH и доставляются на `localhost:5432` **с точки зрения host2**. «localhost» здесь это **сам host2**, а не ваш ПК.

Так ваш клиент PostgreSQL подключается к `127.0.0.1:9999` на ПК, а на самом деле общается с базой на host2, которая принимает только локальные подключения.

### Пример с синим и красным серверами со слайдов

- **Синий сервер** доступен по SSH.
- **Красный сервер** находится за ним и с вашего ПК недоступен.
- `ssh -L 8080:red:80 user@blue` делает так, что `http://127.0.0.1:8080` на вашем ПК показывает веб-страницу красного. Соединение к красному за вас открывает SSH-сервер (синий).

![SSH-туннель проводит незашифрованный сервис через файрвол (слайд курса)](/img/mtcse/se5-09.webp)

### RouterOS как SSH-сервер

Сначала маршрутизатор должен разрешить проброс:

    /ip ssh set forwarding-enabled=both

![Локальная переадресация через RouterOS по шагам (слайд курса)](/img/mtcse/se5-10.webp)

Значения: **no** (по умолчанию), **local** (`-L` от клиентов), **remote** (`-R`), **both**.

### Пример: WebFig через SSH с PuTTY

На маршрутизаторе открыт только SSH. Вам нужен WebFig без открытия HTTP.

**Linux/macOS:**

    ssh -L 2000:127.0.0.1:80 admin@router

Откройте в браузере `http://127.0.0.1:2000`: вы видите **WebFig** маршрутизатора, переданный зашифрованным внутри SSH.

**Windows (PuTTY)**: Connection → SSH → Tunnels, *Source port* 80 (или 2000), *Destination* `127.0.0.1:80`, нажмите Add, затем подключитесь. В командной строке, как на слайде: `putty -L 80:127.0.0.1:80 router`.

Обратите внимание: в обоих случаях **127.0.0.1 интерпретирует SSH-сервер** (маршрутизатор), то есть это WebFig самого маршрутизатора.

### Удалённый проброс: ssh -R

Обратное направление: `ssh -R 8080:localhost:80 server` делает так, что порт 8080 на **сервере** пробрасывается обратно на порт 80 **вашей** машины. Полезно, чтобы временно дать поддержке доступ через промежуточный хост.

> Посмотрите симулятор **Конструктор SSH-туннеля**: он показывает, где интерпретируется каждый адрес в строке `-L`.
