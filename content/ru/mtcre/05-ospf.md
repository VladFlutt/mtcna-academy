# Lesson: Динамическая маршрутизация и OSPF

Статическая маршрутизация требует человека для каждого изменения. Уже при трёх маршрутизаторах в треугольнике нужно шесть маршрутов, плюс резервные и check-gateway для переключения. При двадцати маршрутизаторах это неуправляемо.

**Протокол динамической маршрутизации** позволяет маршрутизаторам рассказывать друг другу, что им доступно, и пересчитывать маршруты, когда что-то меняется. Что это даёт: отказоустойчивость без скриптов, распределение нагрузки по равным путям и сеть, которая растёт без правки каждого маршрутизатора.

## IGP и EGP

- **Протоколы внутренней маршрутизации** (IGP) работают внутри сети одной организации, *автономной системы* (AS): RIP, OSPF, IS-IS, EIGRP.
- **Протоколы внешней маршрутизации** (EGP) работают между автономными системами: BGP, протокол Интернета.

## Дистанционно-векторные и протоколы состояния каналов

- **Distance vector** (RIP): каждый маршрутизатор говорит соседям «я достаю до X на расстоянии N». Всю сеть не видит никто. Просто, но медленно сходится, ограничено 15 переходами и считает переходы, а не полосу.
- **Link state** (OSPF, IS-IS): каждый маршрутизатор описывает свои каналы, и это описание рассылается всем маршрутизаторам области. У всех одна и та же карта (*база данных состояния каналов*), и каждый сам считает кратчайшие пути алгоритмом Дейкстры. Быстрая сходимость, нет ограничения на число переходов, пути выбираются по стоимости.

## OSPF вкратце

**Open Shortest Path First** является открытым стандартным IGP типа link state.

- OSPFv2 (RFC 2328) маршрутизирует IPv4; OSPFv3 (RFC 5340) маршрутизирует IPv6 (RouterOS 7 умеет запускать v3 и для IPv4).
- Пакеты OSPF передаются прямо в IP, **протокол 89** (без TCP или UDP).
- Соседи находятся с помощью multicast-пакетов **hello** на **224.0.0.5** (все OSPF-маршрутизаторы). В broadcast-сетях обновления для выделенных маршрутизаторов идут на **224.0.0.6**.
- Обновления отправляются при изменениях, а не периодически (кроме обновления раз в 30 минут).
- У каждого маршрутизатора есть 32-битный **router ID**, записанный как IP-адрес. Он должен быть уникальным.
- Большие сети делятся на **области** (урок 4).
- Distance в RouterOS: 110.

# Lesson: Соседи и смежности

Прежде чем обмениваться маршрутами, маршрутизаторы должны стать соседями. Каждый интерфейс OSPF отправляет hello каждые **hello-interval** (по умолчанию 10 с). Если от соседа нет hello в течение **dead-interval** (40 с, четыре hello), сосед объявляется мёртвым.

Два маршрутизатора становятся соседями, только если совпадают:

- **area ID** интерфейсов;
- **подсеть и маска** интерфейсов (в сетях broadcast и NBMA);
- **интервалы hello и dead**;
- тип и ключ **аутентификации**;
- **флаги типа области** (stub, NSSA) в hello;
- для полной смежности ещё и **MTU** интерфейса (проверяется при обмене базами).

И router ID должны различаться.

## Состояния соседа

![Состояния, через которые проходит сосед, пока базы состояния каналов не синхронизируются](/img/mtcre/ospf-states.svg)

| Состояние | Значение |
|---|---|
| Down | hello не получен (в последнее время) |
| Attempt | только NBMA: маршрутизатор пытается связаться с настроенным соседом |
| Init | hello получен, но нашего router ID в нём ещё нет (связь в одну сторону) |
| 2-Way | оба видят друг друга в hello. В broadcast-сетях здесь проходят выборы DR/BDR |
| ExStart | двое решают, кто будет master при обмене базами |
| Exchange | обмениваются описаниями базы (DD): списком имеющихся LSA |
| Loading | каждый запрашивает недостающие LSA |
| Full | базы одинаковы: смежность установлена |

Полезные симптомы: **застрял в Init** значит, hello ходят только в одну сторону (фильтрация, неправильный multicast); **застрял в ExStart или Exchange** обычно значит несовпадение MTU.

## Типы сетей

OSPF ведёт себя по-разному в зависимости от типа канала.

| Тип | Пример | DR/BDR | Как находятся соседи |
|---|---|---|---|
| broadcast | Ethernet с несколькими маршрутизаторами | да | multicast hello |
| point-to-point (ptp) | два маршрутизатора на кабеле, PPP, GRE | нет | multicast hello |
| point-to-multipoint (ptmp) | хаб и филиалы в общей среде | нет | multicast hello |
| NBMA | среда без multicast | да | соседи настраиваются вручную |

Для Ethernet по умолчанию используется broadcast. Если на Ethernet-канале только два маршрутизатора, поставьте интерфейсу тип **ptp**: нет выборов DR и сходимость быстрее. Слайды курса рекомендуют это для каждого кабеля между маршрутизаторами.

## DR и BDR

В broadcast-сегменте из n маршрутизаторов полная сетка дала бы n(n−1)/2 смежностей, и в каждой передавались бы одни и те же LSA. Вместо этого маршрутизаторы выбирают **выделенный маршрутизатор** (designated router, DR) и **резервный выделенный маршрутизатор** (BDR). Каждый маршрутизатор устанавливает полную смежность только с DR и BDR; остальные (**DROther**) остаются друг с другом в 2-Way.

![Шесть маршрутизаторов в одном сегменте: все в Full с DR и BDR, DROther между собой в 2-Way](/img/mtcre/ospf-dr.svg)

- Маршрутизаторы отправляют обновления на 224.0.0.6 (DR и BDR); DR рассылает их всем на 224.0.0.5.
- DR также создаёт **network LSA** (тип 2) для сегмента.
- Если DR отказывает, BDR сразу занимает его место и выбирается новый BDR.

**Выборы:** выигрывает наибольший **приоритет** интерфейса (от 0 до 255; по умолчанию 128 в RouterOS 7 и 1 в RouterOS 6); при равном приоритете выигрывает наибольший **router ID**. Приоритет 0 означает, что маршрутизатор никогда не станет DR или BDR.

Выборы **не вытесняющие**. Маршрутизатор, который появился позже с более высоким приоритетом, не забирает роль; он ждёт, пока DR откажет. На практике DR и BDR становятся первые включившиеся маршрутизаторы. Чтобы управлять результатом, задайте приоритеты и перезапустите OSPF в сегменте. Посчитайте смежности сами в симуляторе **Выборы DR/BDR**.

# Lesson: LSA и кратчайший путь

**Link-state advertisement** (LSA) является куском карты сети. Каждый маршрутизатор хранит все LSA своей области в **базе состояния каналов** (LSDB). У маршрутизаторов одной области LSDB одинаковые.

| Тип | Название | Кто создаёт | Что описывает | Где распространяется |
|---|---|---|---|---|
| 1 | Router | каждый маршрутизатор | свои каналы в области и их стоимости | внутри области |
| 2 | Network | DR | маршрутизаторы broadcast-сегмента | внутри области |
| 3 | Summary | ABR | сети других областей | в область |
| 4 | ASBR summary | ABR | как добраться до ASBR в другой области | в область |
| 5 | External | ASBR | маршруты, перераспределённые извне OSPF | по всей AS (не в stub-области) |
| 7 | NSSA external | ASBR в NSSA | внешние маршруты внутри NSSA | внутри NSSA; ABR преобразует их в тип 5 |

Типы 6 и 8–11 существуют (multicast, атрибуты, opaque), но в курс не входят.

У каждого LSA есть номер последовательности и возраст. Более новый номер заменяет старую копию; LSA обновляется каждые 30 минут и устаревает через 60 минут (MaxAge).

## Стоимость

У каждого интерфейса OSPF есть **стоимость** (cost). Стоимость пути равна сумме стоимостей исходящих интерфейсов на нём, и выигрывает наименьшая сумма. Стандартная формула: *опорная полоса / полоса интерфейса* (при опорной 100 Мбит/с канал 10 Мбит/с получает стоимость 10). RouterOS не вычисляет стоимость из скорости канала: каждый интерфейс получает одну и ту же стоимость по умолчанию (1 в RouterOS 7, 10 в RouterOS 6), а там, где нужно направить трафик, стоимости задаёте вы.

## SPF

Каждый маршрутизатор выполняет алгоритм Дейкстры **shortest path first** над LSDB, взяв себя за корень:

1. корень в дереве со стоимостью 0;
2. посмотреть на соседей только что добавленного маршрутизатора и записать суммарную стоимость до каждого (если уже записана, оставить меньшую);
3. перенести в дерево кандидата с наименьшей суммарной стоимостью;
4. повторять, пока все маршрутизаторы не окажутся в дереве.

Результат: дерево кратчайших путей от этого маршрутизатора до каждого назначения. Если у двух путей одинаковая сумма, сохраняются оба: OSPF умеет ECMP.

![Пути с их суммарной стоимостью: R1 достаёт до 192.168.2.0/24 со стоимостью 40 вместо 70 через канал со стоимостью 50 (слайд курса)](/img/mtcre/re-ospf-cost.webp)

Запустите **Пошаговый SPF в OSPF**: меняйте стоимости, проходите алгоритм по шагам и смотрите, как перестраивается дерево.

# Lesson: Области и роли маршрутизаторов

В одной большой области каждый маршрутизатор хранит все LSA, и каждое изменение канала запускает SPF на каждом маршрутизаторе. Слайды курса оценивают комфортный размер одной области примерно в 80 маршрутизаторов. **Области** делят сеть: подробности остаются внутри области, другие области видят только суммарные сведения.

- У областей 32-битный ID, записанный как адрес: 0.0.0.0, 0.0.0.1…
- **Область 0** (0.0.0.0) является **магистралью** (backbone). Каждая другая область должна быть подключена к ней, напрямую или через *virtual link*. Трафик между двумя немагистральными областями всегда проходит через магистраль.

![Магистраль, области и роли маршрутизаторов (слайд курса)](/img/mtcre/re-ospf-areas-cloud.webp)

## Роли маршрутизаторов

| Роль | Определение |
|---|---|
| Внутренний маршрутизатор (IR) | все интерфейсы в одной области |
| Магистральный маршрутизатор | хотя бы один интерфейс в области 0 |
| ABR (area border router) | интерфейсы в двух и более областях, одна из них область 0; суммирует (LSA 3) |
| ASBR (AS boundary router) | перераспределяет маршруты извне OSPF (static, connected, BGP) как LSA 5 или 7 |

## Типы маршрутов

OSPF предпочитает маршруты в таком порядке, независимо от стоимости:

1. **внутриобластные** (из LSA 1 и 2);
2. **межобластные** (LSA 3);
3. **внешние типа 1** (E1): стоимость = внешняя метрика + внутренняя стоимость до ASBR;
4. **внешние типа 2** (E2): стоимость = только внешняя метрика; внутренняя стоимость лишь разрешает ничью.

E2 используется по умолчанию для перераспределённых маршрутов. В модуле 6 показано, когда лучше выбрать E1.

## Типы областей

| Тип области | LSA 3 | LSA 4/5 | LSA 7 | Маршрут по умолчанию |
|---|---|---|---|---|
| магистраль, обычная | да | да | нет | только если кто-то его создаёт |
| stub | да | нет | нет | ABR добавляет 0.0.0.0/0 (LSA 3) |
| totally stubby | только маршрут по умолчанию | нет | нет | ABR добавляет 0.0.0.0/0 |
| NSSA | да | нет | да | не автоматически |
| totally NSSA | только маршрут по умолчанию | нет | да | ABR добавляет 0.0.0.0/0 |

- В **stub**-области не может быть ASBR. Её маршрутизаторам не нужны внешние маршруты, потому что любой выход всё равно идёт через ABR: достаточно маршрута по умолчанию.
- **Totally stubby**-область отбрасывает ещё и межобластные суммарные маршруты. Её маршрутизаторы знают свою область плюс маршрут по умолчанию.
- **NSSA** (not-so-stubby area) является stub-областью, в которой может быть ASBR. Её внешние маршруты идут как LSA 7, а ABR преобразует их в LSA 5 для остальной сети.

![Stub-область: маршрутизаторы области 1 теряют внешние маршруты и получают вместо них маршрут по умолчанию от ABR (слайд курса, синтаксис RouterOS 6)](/img/mtcre/re-ospf-stub.webp)

![Totally stubby: межобластные маршруты тоже заменяются маршрутом по умолчанию (слайд курса)](/img/mtcre/re-ospf-totally-stubby.webp)

Все маршрутизаторы области должны быть согласны с её типом: флаг stub передаётся в hello, и несовпадение не даёт стать соседями. Сравните типы в симуляторе **Типы областей OSPF и LSA**.

![Области, ABR и ASBR, и какие LSA попадают в какой тип области](/img/mtcre/ospf-areas.svg)
