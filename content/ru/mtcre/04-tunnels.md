# Lesson: Адресация точка-точка

Каналу между двумя маршрутизаторами нужны адреса на обоих концах. Обычно берут /30: четыре адреса, из которых два пригодны (сеть, маршрутизатор A, маршрутизатор B, broadcast).

    R1: /ip address add address=10.0.12.1/30 interface=ether1
    R2: /ip address add address=10.0.12.2/30 interface=ether1

Половина адресов пропадает зря, а это важно при публичных адресах и сотнях туннелей.

## Адреса /32 с network=

RouterOS умеет ставить адрес /32 на интерфейс точка-точка и называть другой конец через `network=`:

    R1: /ip address add address=10.1.1.1/32 network=10.1.1.2 interface=ipip1
    R2: /ip address add address=10.1.1.2/32 network=10.1.1.1 interface=ipip1

RouterOS создаёт connected-маршрут к единственному адресу 10.1.1.2/32 через этот интерфейс. С каждой стороны используется только один адрес, а центральный маршрутизатор может даже использовать **один и тот же адрес** на всех своих туннелях: у каждого туннеля свой `network=` (адрес филиала).

![Один и тот же адрес хаба 10.1.1.1/32 на трёх туннелях, каждый указывает на свой филиал (слайд курса)](/img/mtcre/re-p2p-32.webp)

Именно так работает PPP: PPP-сервер даёт своей стороне local address, а клиенту remote address, и оба выглядят как адреса /32 с адресом пира в качестве network. Лаба курса просит заменить адреса туннеля /30 на /32 и проверить, что маршрутизация продолжает работать.

Возможны также **unnumbered**-каналы (интерфейс в качестве шлюза, маршрутизатор использует адрес loopback как источник). А VLAN из следующего урока позволяют пропустить много таких каналов по одному кабелю.

> RouterOS 6 и 7 используют одинаковый синтаксис для `network=`.

# Lesson: VLAN между маршрутизаторами

VLAN делит один физический канал на несколько логических. Каждый Ethernet-кадр получает 4-байтовый **тег 802.1Q** с 12-битным **VLAN ID** (от 1 до 4094; 0 и 4095 зарезервированы). На одном кабеле оба конца должны использовать одинаковый VLAN ID.

    /interface vlan add name=vlan10 vlan-id=10 interface=ether1
    /ip address add address=10.10.10.1/30 interface=vlan10

VLAN-интерфейс ведёт себя как обычный Ethernet-интерфейс: на нём есть адреса, маршруты и правила firewall. Между маршрутизаторами это самый дешёвый способ получить несколько разделённых каналов (транзит, управление, клиенты) по одному кабелю или подключиться к провайдеру, который отдаёт услуги в разных VLAN.

- Тег занимает 4 байта **L2 MTU**. У Ethernet-портов RouterBOARD L2 MTU больше 1500, поэтому IP MTU у VLAN-интерфейса остаётся 1500.
- VLAN-интерфейс создаётся на физическом порту или на bridge, если bridge передаёт тегированный трафик (bridge VLAN filtering относится к коммутации и разбирается в MTCSWE).
- VLAN 1 на коммутаторах часто является нетегированным VLAN по умолчанию; не используйте его для тегированных каналов.

В лабе **VLAN и адресация точка-точка** вы пропускаете два VLAN между двумя маршрутизаторами по одному кабелю: VLAN 10 с /30 для транзитного маршрута и VLAN 99 с адресами /32 точка-точка для управления.

# Lesson: Туннели IPIP и GRE

Туннель кладёт пакет внутрь другого пакета, чтобы тот прошёл через сеть, которая не знает его адресов. Классический случай: два офиса с частными LAN (192.168.10.0/24, 192.168.20.0/24), соединённые через Интернет. У маршрутизаторов Интернета нет маршрутов в частные сети, но между публичными адресами офисов они маршрутизируют.

Туннели этого модуля **без состояния** (stateless): концы ни о чём не договариваются, а просто инкапсулируют. Поэтому они простые и быстрые, но без шифрования и без аутентификации.

| | IPIP | GRE | EoIP |
|---|---|---|---|
| Что несёт | только IPv4 | любой протокол L3 (IP, multicast для OSPF) | Ethernet-кадры (уровень 2) |
| Протокол | IP protocol 4 (RFC 2003) | IP protocol 47 (RFC 1701/2784) | GRE (собственный формат MikroTik) |
| Накладные расходы | 20 байт | 24 байта | 42 байта |
| MTU по умолчанию в RouterOS | 1480 | 1476 | 1458 (actual MTU) |
| Можно добавить в bridge | нет | нет | да |

## Настройка

Оба конца указывают на публичный адрес друг друга:

    HQ: /interface gre add name=gre-br local-address=22.1.1.2 remote-address=33.1.1.2
    BR: /interface gre add name=gre-hq local-address=33.1.1.2 remote-address=22.1.1.2
    HQ: /ip address add address=172.16.0.1/30 interface=gre-br
    BR: /ip address add address=172.16.0.2/30 interface=gre-hq
    HQ: /ip route add dst-address=192.168.20.0/24 gateway=172.16.0.2
    BR: /ip route add dst-address=192.168.10.0/24 gateway=172.16.0.1

IPIP настраивается так же через `/interface ipip`.

![GRE между двумя офисами в Winbox; с IPsec secret на обеих сторонах RouterOS автоматически добавляет IPsec в транспортном режиме (слайд курса)](/img/mtcre/re-gre-winbox.webp)

## keepalive

Без keepalive туннель без состояния всегда *running*, даже если другого конца уже нет, поэтому маршруты через него остаются активными. С `keepalive=10s,10` маршрутизатор каждые 10 секунд отправляет keepalive и переводит туннель в down после 10 пропущенных ответов. Тогда маршруты через туннель становятся неактивными, и работу может взять резервный маршрут (или OSPF). RouterOS по умолчанию добавляет keepalive новым туннелям GRE и IPIP; проверьте, что дальний конец на него отвечает.

## Безопасность

GRE и IPIP не шифруются. `ipsec-secret=` на обоих концах заставляет RouterOS автоматически построить для туннеля политику IPsec в транспортном режиме (динамические peer и policy, pre-shared key). Для всего, что идёт через Интернет, используйте это или WireGuard.

## MTU и фрагментация

Туннель добавляет заголовок, поэтому полноразмерный пакет 1500 байт из LAN уже не помещается в канал Интернета с MTU 1500. Его придётся фрагментировать или отбросить, если стоит бит *don't fragment*; тогда большие загрузки зависают, а маленькие страницы открываются. Ограничьте TCP MSS для трафика в туннель:

    /ip firewall mangle add chain=forward protocol=tcp tcp-flags=syn out-interface=gre-br \
        action=change-mss new-mss=clamp-to-pmtu passthrough=yes

![Накладные расходы заголовков для каждого типа туннеля](/img/mtcre/tunnel-encap.svg)

В симуляторе **Накладные расходы туннелей и MTU** сложите несколько инкапсуляций (например, GRE поверх PPPoE с IPsec) и посмотрите, какой MTU остаётся.

## Ловушка рекурсивной маршрутизации

Удалённый адрес туннеля должен быть доступен **вне** туннеля. Если добавить маршрут к удалённому публичному адресу через сам туннель (часто случайно, суммарным маршрутом или маршрутом по умолчанию через туннель), пакеты туннеля пытаются идти через туннель, туннель падает, маршрут исчезает, туннель поднимается… RouterOS пишет в лог об ошибке рекурсивной маршрутизации. Держите точный маршрут к публичному адресу дальнего конца через настоящий аплинк.

# Lesson: EoIP: второй уровень поверх IP

**Ethernet over IP** является собственным туннелем MikroTik. Он передаёт целые Ethernet-кадры, поэтому интерфейс туннеля можно добавить в bridge: оба офиса оказываются в одном широковещательном домене, в одной подсети, даже с одним DHCP-сервером.

    HQ: /interface eoip add name=eoip-br local-address=22.1.1.2 remote-address=33.1.1.2 tunnel-id=10
    BR: /interface eoip add name=eoip-hq local-address=33.1.1.2 remote-address=22.1.1.2 tunnel-id=10
    both: /interface bridge add name=br-lan
          /interface bridge port add bridge=br-lan interface=ether5
          /interface bridge port add bridge=br-lan interface=eoip-...

- **tunnel-id** должен совпадать на обоих концах и быть уникальным для одной пары адресов; он позволяет запустить несколько EoIP-туннелей между одними и теми же маршрутизаторами.
- У интерфейсов EoIP есть MAC-адрес (сгенерированный); следите, чтобы он был уникален, если клонируете конфигурации.
- MTU: Ethernet-кадр 1500 байт плюс 42 байта заголовков не помещаются в аплинк с MTU 1500; RouterOS фрагментирует внешние пакеты. Это работает, но стоит производительности; где можно, ограничивайте MSS.
- Второй уровень через WAN переносит через канал broadcast и ARP, а второй путь в bridge может создать петлю. Объединяйте в bridge только там, где действительно нужна одна подсеть на два офиса (старые устройства, перенос виртуальных машин); в остальных случаях маршрутизируйте.

![EoIP, добавленный в bridge с LAN на обоих маршрутизаторах: одна подсеть 192.168.1.0/24 на два офиса (слайд курса)](/img/mtcre/re-eoip-winbox.webp)

Как и GRE, EoIP поддерживает `keepalive` и `ipsec-secret`.

# Lesson: WireGuard (RouterOS 7)

WireGuard является современным шифрованным туннелем, встроенным в RouterOS 7. Он работает поверх UDP, использует фиксированную современную криптографию (Curve25519, ChaCha20-Poly1305, BLAKE2s) и очень небольшой код. Договариваться не о чем: у каждой стороны есть пара ключей, и каждая знает открытый ключ другой.

    HQ: /interface wireguard add name=wg1 listen-port=13231
    BR: /interface wireguard add name=wg1 listen-port=13231
        /interface wireguard print          (показывает public-key, который нужно скопировать)

При создании интерфейса генерируются закрытый и открытый ключи. Затем каждый маршрутизатор получает **peer** для другого:

    HQ: /interface wireguard peers add interface=wg1 public-key="<BR public key>" \
            endpoint-address=33.1.1.2 endpoint-port=13231 allowed-address=10.255.255.2/32,192.168.20.0/24
    BR: /interface wireguard peers add interface=wg1 public-key="<HQ public key>" \
            allowed-address=10.255.255.1/32,192.168.10.0/24

![Открытый ключ каждого маршрутизатора вписывается в peer на другом маршрутизаторе (слайд курса)](/img/mtcre/re-wg-keys.webp)

## allowed-address

`allowed-address` является сердцем WireGuard. Для пира он перечисляет адреса, которые можно **отправлять** этому пиру и **принимать** от него. Пакет из туннеля с источником вне списка отбрасывается; пакет, направленный в wg1 с назначением вне списков всех пиров, тоже отбрасывается. Если на одном интерфейсе несколько пиров, allowed-address решает, какой пир получит какой пакет.

Маршруты всё равно нужны: в RouterOS allowed-address не создаёт маршрутов. Направьте удалённую LAN в интерфейс WireGuard:

    HQ: /ip address add address=10.255.255.1/30 interface=wg1
    HQ: /ip route add dst-address=192.168.20.0/24 gateway=10.255.255.2

## endpoint и persistent-keepalive

Хотя бы у одной стороны должен быть `endpoint-address` (куда отправлять). Другая сторона узнаёт endpoint из первого корректного пакета; так филиал за NAT с динамическим адресом подключается к центральному офису с постоянным адресом. На стороне за NAT поставьте `persistent-keepalive=25s`, чтобы трансляция NAT оставалась открытой.

## MTU

WireGuard добавляет 60 байт поверх IPv4 (80 поверх IPv6); MTU интерфейса по умолчанию 1420.

> **В RouterOS 6** WireGuard нет. Используйте IPsec или GRE/IPIP/EoIP с ipsec-secret.

Постройте все три типа туннелей в лабах. Потом сравните: GRE требует публичного адреса на обоих концах и не шифруется; WireGuard работает за NAT и шифруется; EoIP единственный даёт второй уровень.
