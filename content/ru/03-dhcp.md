# Lesson: Как работает DHCP

**DHCP** (Dynamic Host Configuration Protocol) автоматически выдаёт клиентам IP-адрес, маску, шлюз, DNS-серверы и другие параметры. Использует **UDP 67** (сервер) и **UDP 68** (клиент).

### DORA

1. **Discover**: клиент отправляет широковещательный запрос «есть ли DHCP-сервер?»
2. **Offer**: сервер предлагает адрес.
3. **Request**: клиент запрашивает предложенный адрес.
4. **Acknowledge**: сервер подтверждает; аренда начинается.

Клиент продлевает аренду по истечении половины **lease time**.

> DHCP-сервер отвечает только на том интерфейсе, на котором он настроен. Если интерфейс является **портом бриджа**, сервер должен быть на **бридже**, а не на порту.

# Lesson: DHCP-клиент

DHCP-клиент используется на стороне WAN, обычно на ether1:

    /ip dhcp-client add interface=ether1 disabled=no

Важные опции:

- **use-peer-dns** (по умолчанию yes): принимать DNS-серверы от сервера.
- **use-peer-ntp**: принимать NTP-серверы.
- **add-default-route** (по умолчанию yes): добавить маршрут по умолчанию через полученный шлюз; **default-route-distance** (по умолчанию 1).

Проверка: `/ip dhcp-client print` показывает **status=bound** и полученный адрес. Адрес появляется в `/ip address` с флагом **D** (dynamic).

# Lesson: DHCP-сервер

### Быстрая настройка

Проще всего мастер настройки: **IP > DHCP Server > DHCP Setup** или `/ip dhcp-server setup`. Он спрашивает интерфейс, сеть, шлюз, пул, DNS и время аренды.

### Что создаёт мастер

DHCP-серверу нужны **три** вещи:

1. **IP pool**: `/ip pool add name=lan-pool ranges=192.168.88.10-192.168.88.254`
2. **DHCP server**, привязанный к интерфейсу и пулу: `/ip dhcp-server add name=dhcp1 interface=bridge address-pool=lan-pool disabled=no`
3. **DHCP network** с выдаваемыми параметрами: `/ip dhcp-server network add address=192.168.88.0/24 gateway=192.168.88.1 dns-server=192.168.88.1`

И у самого интерфейса должен быть IP-адрес из этой сети (192.168.88.1/24).

### Аренды

**IP > DHCP Server > Leases** показывает всех клиентов. Флаги: **D** динамическая, **B** заблокированная. Нажмите **Make Static**, чтобы всегда выдавать этому MAC один и тот же адрес, или добавьте вручную:

    /ip dhcp-server lease add address=192.168.88.50 mac-address=AA:BB:CC:DD:EE:FF

**lease-time** по умолчанию 30 минут в v7 (10 минут в некоторых версиях v6).

### DHCP и ARP

Опция DHCP-сервера **add-arp=yes** добавляет статическую запись ARP для каждой аренды. Вместе с **arp=reply-only** на интерфейсе связь получают только хосты, получившие адрес по DHCP: простая защита от пользователей, вручную задающих статические IP.

### Лабы курса

**Лаба 5.11 (DHCP-клиент)**

1. Удалите статический IP с WAN (ether1) и маршрут по умолчанию 0.0.0.0/0.
2. Должны остаться только IP LAN на бридже и один маршрут DAC к вашей LAN.
3. Добавьте DHCP-клиент на ether1 и проверьте полученные **IP**, **маршрут по умолчанию** и **DNS**.
4. Проверьте Интернет на ноутбуке.

**Лаба 5.12 (DHCP-сервер)**

1. Запустите DHCP-сервер на вашем **бридже** (интерфейс LAN) с помощью мастера.
2. Настройте ноутбук на *автоматическое получение IP*.
3. Проверьте **Leases**.

Мастер спрашивает по порядку: интерфейс, адресное пространство, шлюз, выдаваемые адреса, DNS-серверы, время аренды. В RouterOS v6 время аренды по умолчанию **10 минут** (v7: 30 минут). Короткие аренды подходят для загруженных гостевых сетей; в офисных сетях можно использовать часы или дни.

Вопросы для размышления: можно ли держать больше одного DHCP-сервера в одном широковещательном домене? (Нет, клиенты будут получать случайные ответы: rogue DHCP это классическая проблема.) На каком уровне OSI работает DHCP? (Прикладной уровень, переносится по UDP 67/68.)

# Lesson: ARP

**ARP** сопоставляет IP-адреса с MAC-адресами. Смотрите в **IP > ARP** (`/ip arp print`).

Режимы ARP на интерфейсе:

| Режим | Поведение |
|---|---|
| **enabled** (по умолчанию) | Обычное изучение и ответы ARP |
| **disabled** | ARP не используется; у соседей должны быть статические записи для маршрутизатора |
| **reply-only** | Отвечает только для адресов со **статическими** записями ARP; новые записи не изучаются |
| **proxy-arp** | Отвечает на ARP от имени хостов в других сетях |
| **local-proxy-arp** | Proxy ARP между хостами на одном интерфейсе |

    /ip arp add address=192.168.88.20 mac-address=11:22:33:44:55:66 interface=bridge
    /interface bridge set bridge arp=reply-only

Из курса:

- Запись ARP содержит **IP-адрес, MAC-адрес и интерфейс**.
- Щёлкните правой кнопкой по динамической записи и выберите **Make Static**, чтобы закрепить её.
- Максимальное число записей ARP по умолчанию **8192** (IP > Settings, *max-arp-entries* в v7).
- При **arp=reply-only** маршрутизатор только отвечает на ARP и не добавляет записи в свою таблицу; соседей нужно добавить статически в /ip arp. При **arp=disabled** нужно также добавить MAC маршрутизатора в таблицы ARP других хостов.

# Lesson: DNS на маршрутизаторе

В RouterOS есть кэширующий DNS-сервер:

    /ip dns set servers=8.8.8.8,1.1.1.1 allow-remote-requests=yes

- **allow-remote-requests=yes** позволяет клиентам LAN использовать маршрутизатор как DNS (выдавайте IP маршрутизатора как DNS в DHCP).
- Если вы это включили, **заблокируйте** UDP/TCP 53 из WAN в цепочке input файрвола, иначе маршрутизатор станет открытым резолвером.
- Статические записи: `/ip dns static add name=router.lan address=192.168.88.1`
