# Lesson: Как DNS разрешает имя

Люди запоминают имена, маршрутизаторам нужны адреса. **Система доменных имён** превращает www.example.com в адрес. Это распределённая база данных в виде дерева, которое читается справа налево:

| Часть | Пример | Кто за неё отвечает |
|---|---|---|
| корень | `.` (обычно не пишется) | 13 имён корневых серверов, которые обслуживают разные организации |
| домен верхнего уровня (TLD) | `com`, `org`, `ru`, `lv` | регистратура этого TLD |
| домен | `example` | DNS-серверы, которые указал владелец |
| хост или поддомен | `www`, `mail`, `vpn` | те же DNS-серверы |

**Резолвер**, которому нужен www.example.com, спрашивает корневой сервер, тот отсылает его к серверам com, те к серверам example.com, которые и дают ответ. У каждого ответа есть **TTL** (время жизни): сколько его можно хранить в кэше.

Частые типы записей:

| Тип | Содержит |
|---|---|
| A | IPv4-адрес |
| AAAA | IPv6-адрес |
| CNAME | другое имя (псевдоним) |
| MX | почтовые серверы домена |
| NS | DNS-серверы зоны |
| PTR | имя для адреса (обратный запрос) |
| TXT | произвольный текст (SPF, подтверждения) |

DNS использует **UDP 53** для обычных запросов и **TCP 53** для ответов, которые не помещаются в один UDP-пакет, и для передачи зон. Файрвол должен учитывать оба.

# Lesson: Маршрутизатор как кэширующий DNS-сервер

В RouterOS DNS-клиент и **кэширующий DNS-сервер** находятся в одном меню, `/ip dns`.

    /ip dns set servers=1.1.1.1,8.8.8.8 allow-remote-requests=yes
    /ip dns print

- **servers**: вышестоящие серверы, которые спрашивает маршрутизатор. Серверы, полученные DHCP-клиентом или PPP-подключением с `use-peer-dns=yes`, добавляются как **динамические**.
- **allow-remote-requests=yes**: другие устройства могут использовать маршрутизатор как свой DNS-сервер. Без этого маршрутизатор разрешает имена только для себя (ping, NTP, address lists с именами).
- **cache-size** (по умолчанию 2048 КиБ) и **cache-max-ttl** (1 неделя): сколько хранить и как долго максимум.
- **max-udp-packet-size** (4096): самый большой UDP-ответ, который принимает маршрутизатор (EDNS).
- **query-server-timeout** и **query-total-timeout**: сколько ждать один сервер и весь запрос.
- RouterOS 7 добавляет **use-doh-server**: маршрутизатор сам спрашивает вышестоящий сервер через DNS over HTTPS.

Кэш находится в `/ip dns cache`; `/ip dns cache flush` очищает его. Это первое, что нужно сделать, если изменившийся адрес в Интернете у вас всё ещё разрешается в старый (у клиентов тоже есть свои кэши).

## Открытые резолверы

С `allow-remote-requests=yes` маршрутизатор отвечает любому, кто достаёт до UDP или TCP 53. На публичном адресе без файрвола он становится **открытым резолвером**, которым атакующие пользуются для DNS-амплификации: маленький запрос с подменённым источником порождает большой ответ жертве. Всегда отбрасывайте DNS из WAN:

    /ip firewall filter add chain=input in-interface-list=WAN protocol=udp dst-port=53 action=drop
    /ip firewall filter add chain=input in-interface-list=WAN protocol=tcp dst-port=53 action=drop

Конфигурация по умолчанию и файрвол, заканчивающийся правилом «отбросить всё не из LAN», это уже покрывают.

# Lesson: Статические записи и регулярные выражения

Статические записи отвечают раньше кэша и вышестоящих серверов:

    /ip dns static add name=comp1.local address=192.168.33.10
    /ip dns static add name=mail.server address=192.168.33.200
    /ip dns static add name=router.lan address=192.168.33.1

Применение: имена локальных серверов, подмена публичного имени (отправить mail.example.com на внутренний почтовый сервер) и блокировка.

- Записи проверяются **сверху вниз**, отвечает первое совпадение.
- Статическая запись A автоматически отвечает и на соответствующий обратный запрос (PTR).
- У записей RouterOS 7 есть **type**: A, AAAA, CNAME, MX, NS, SRV, TXT, **FWD** и **NXDOMAIN**.
- `match-subdomain=yes` заставляет `name=corp.local` отвечать и для `pc1.corp.local`.

## Пересылка домена

    /ip dns static add name=corp.local type=FWD forward-to=10.1.1.53 match-subdomain=yes

Запросы для corp.local и всего под ним уходят на DNS-сервер офиса, остальные на обычные вышестоящие серверы. Так филиал разрешает внутренние имена головного офиса через VPN.

## Регулярные выражения

Вместо имени у записи может быть **regexp**:

    /ip dns static add regexp="(^|\\.)ads\\.example\\.com\$" address=127.0.0.1

- Выражение это регулярное выражение POSIX, которое сравнивается со всем именем из запроса.
- `.` означает любой символ: настоящую точку экранируйте как `\.`. Внутри двойных кавычек в CLI сам обратный слэш тоже экранируется, поэтому вы пишете `\\.`, а `$` пишется как `\$`, потому что `$` начинает переменную.
- Привязывайте выражение. Без `^` и `$` выражение `ads\.example\.com` совпадёт и с `ads.example.com.evil.net`.
- Записи regexp медленнее обычных имён; держите их немного и ставьте после точных имён.

Блокировка домена: ответ 127.0.0.1 или 0.0.0.0, либо `type=NXDOMAIN`, чтобы клиенту сообщили, что имени не существует. Проверяйте выражения в **проверке шаблонов прокси и DNS**.

# Lesson: Принудительное использование DNS маршрутизатора

Статические записи и блокировка помогают, только если клиенты действительно спрашивают маршрутизатор. Клиент с вручную прописанным 8.8.8.8 обходит его. Правило dstnat перехватывает каждый DNS-запрос из LAN и отправляет его на сам маршрутизатор:

    /ip firewall nat add chain=dstnat in-interface=bridgeLAN protocol=udp dst-port=53 action=redirect to-ports=53
    /ip firewall nat add chain=dstnat in-interface=bridgeLAN protocol=tcp dst-port=53 action=redirect to-ports=53

- **redirect** это dst-nat на собственный адрес маршрутизатора на входящем интерфейсе; `to-ports` выбирает порт.
- Клиент по-прежнему думает, что говорит с 8.8.8.8, и ответ приходит с 8.8.8.8 в качестве источника, потому что отслеживание соединений выполняет обратную трансляцию.
- Нужен `allow-remote-requests=yes`, а цепочка input должна принимать DNS из LAN.

## Ограничения

- **DNS over HTTPS** (DoH) это обычный HTTPS на TCP 443 к адресу резолвера. Redirect порта 53 его не видит. Современные браузеры возвращаются к обычному DNS, если DoH-резолвер недоступен, поэтому блокировка известных адресов DoH (address list) возвращает контроль.
- **DNS over TLS** использует TCP 853, его можно просто заблокировать в forward.

Лаба **DNS** собирает всё это: маршрутизатор отвечает только LAN, знает локальные имена и блокировку по regexp и перехватывает каждый запрос на себя.
