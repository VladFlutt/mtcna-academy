# Lesson: Веб-прокси, обычный и прозрачный

**Веб-прокси** загружает веб-страницы от имени клиентов. В RouterOS он встроен (`/ip proxy`). Он умеет:

- фильтровать запросы по клиенту, хосту, пути и методу (`/ip proxy access`);
- кэшировать ответы и отдавать повторные запросы локально (`/ip proxy cache`);
- передавать запросы **родительскому прокси**, с исключениями (`/ip proxy direct`).

    /ip proxy set enabled=yes port=8080 max-cache-size=unlimited cache-on-disk=no

## Обычный прокси

В обычной (явной) схеме в каждом браузере прописаны адрес и порт прокси. Браузер отправляет запросы на прокси, включая HTTPS как туннель `CONNECT`. Это работает, но настраивать нужно каждое устройство, а пользователь может просто убрать настройку.

## Прозрачный прокси

В прозрачной схеме маршрутизатор сам перенаправляет обычный HTTP на прокси, а клиенты ничего об этом не знают:

    /ip firewall nat add chain=dstnat in-interface=bridgeLAN protocol=tcp dst-port=80 action=redirect to-ports=8080

![Прозрачный прокси: HTTP перенаправляется на прокси, который разрешает или запрещает, отвечает из кэша или загружает страницу](/img/mtctce/proxy-transparent.svg)

- Перенаправленное соединение заканчивается на маршрутизаторе, поэтому проходит цепочку **input**; собственное соединение прокси к веб-серверу идёт через **output**.
- Устройства, которые ломаются за прокси, исключаются правилом `action=accept` в dstnat выше redirect с их адресом.

## HTTPS

Сегодня почти весь веб-трафик это HTTPS. Прозрачный прокси не видит его содержимого: URL, путь и страница зашифрованы из конца в конец, а перенаправление TCP 443 на прокси только ломает соединения. HTTPS фильтруют иначе:

- через **DNS** (статические записи, блокирующие домен, модуль 1);
- через **address lists** с адресами серверов;
- по имени сервера, которое клиент отправляет в рукопожатии TLS: матчер файрвола `tls-host` (например `tls-host=*.example.com`).

## Никогда не оставляйте прокси открытым

Включённый прокси слушает на всех интерфейсах. Доступный из Интернета, он становится **открытым прокси**: спамеры и атакующие используют его, чтобы скрыть свой источник, и ваш адрес за несколько часов попадает в чёрные списки. Отбрасывайте порт прокси из WAN в цепочке input или держите файрвол, отбрасывающий всё не из LAN, и добавьте разрешающее правило только для своих клиентов:

    /ip proxy access add src-address=192.168.33.0/24 action=allow
    /ip proxy access add action=deny

# Lesson: Правила доступа, шаблоны и регулярные выражения

Правила `/ip proxy access` проверяются **сверху вниз**; решает первое совпавшее правило, а запрос без совпадений разрешается.

| Поле | Совпадает с |
|---|---|
| src-address | клиентом |
| dst-address, dst-port | адресом и портом веб-сервера |
| local-port | портом прокси, к которому подключился клиент (если прокси слушает несколько) |
| dst-host | именем хоста в запросе |
| path | частью URL после хоста, например /files/setup.exe |
| method | GET, POST, CONNECT… |
| action | allow или deny |
| redirect-to | для deny: отправить браузер на этот URL вместо страницы ошибки |

    /ip proxy access add dst-host=*mikrotik.com action=deny redirect-to=mt.lv
    /ip proxy access add path=*.exe action=deny
    /ip proxy access add dst-host=":(torrent|piratebay)" action=deny

## Шаблоны

- `*` любое число символов, `?` ровно один.
- Шаблон должен совпасть со **всем** значением: `*mikrotik.com` совпадает с www.mikrotik.com и mikrotik.com, но не с mikrotik.com.evil.net.
- `!` в начале инвертирует совпадение.

## Регулярные выражения

Значение, начинающееся с `:`, это **регулярное выражение**, и без привязки оно совпадает в любом месте.

| Шаблон | Совпадает с |
|---|---|
| `:torrent` | любым хостом, содержащим «torrent» |
| `:^www\.` | хостами, начинающимися с «www.» |
| `:\.ru$` | хостами, заканчивающимися на «.ru» |
| `:^[0-9.]+$` | голым IPv4-адресом вместо имени хоста |

Лаба курса блокирует торрент-сайты одним правилом вроде `dst-host=":(torrent|thepiratebay|rutracker)"` и отправляет пользователей одного сайта на другой через `redirect-to`. Проверяйте шаблоны в **проверке шаблонов прокси и DNS**.

# Lesson: Кэш, прямой доступ и мониторинг

## Кэш

    /ip proxy set max-cache-size=unlimited max-cache-object-size=2048KiB cache-on-disk=yes max-fresh-time=3d

- **max-cache-size** и **cache-on-disk**: кэш хранится в RAM, если не задано `cache-on-disk=yes` (на устройстве с нормальным накопителем).
- **max-fresh-time** (по умолчанию 3 дня): сколько максимум объект считается свежим, если сервер не указал срок.
- Правила `/ip proxy cache` решают, **что можно кэшировать** (allow или deny по хосту, пути…); динамические страницы или чувствительный интранет типичные кандидаты для deny.
- **cache-hit-dscp** (по умолчанию 4) маркирует ответы из кэша этим значением DSCP. Они не использовали канал в Интернет, поэтому очереди могут не ограничивать их, отлавливая `dscp=4` в mangle.

## Родительский прокси и прямой доступ

    /ip proxy set parent-proxy=10.0.0.3 parent-proxy-port=3128
    /ip proxy direct add dst-host=*.local action=allow

С родительским прокси запросы идут к родителю; правила `/ip proxy direct` с `action=allow` отправляют совпавшие запросы напрямую к серверу.

## Мониторинг

- `/ip proxy connections print`: текущие запросы.
- `/ip proxy print stats`: попадания и промахи.
- `/ip proxy cache-contents print`: что лежит в кэше.
- Тема логов `web-proxy` записывает запросы.

Лаба **прозрачный прокси** перенаправляет HTTP, добавляет перенаправление и блокировку по regex и проверяет, что прокси закрыт для WAN.
