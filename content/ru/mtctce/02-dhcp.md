# Lesson: DORA, аренда и таймеры

**Dynamic Host Configuration Protocol** выдаёт устройству адрес и всё, что нужно для работы в сети. Клиент без адреса говорит с сервером широковещательно: с 0.0.0.0, UDP-порт 68, на 255.255.255.255, UDP-порт 67.

![Четыре сообщения DORA и таймеры аренды](/img/mtctce/dhcp-dora.svg)

1. **DISCOVER**: клиент просит адрес у всех серверов сегмента.
2. **OFFER**: каждый сервер, который может ответить, предлагает адрес и опции.
3. **REQUEST**: клиент выбирает одно предложение (обычно первое) и запрашивает его, тоже широковещательно, чтобы остальные серверы узнали, что их не выбрали.
4. **ACK**: выбранный сервер подтверждает. Клиент проверяет через ARP, что адрес никем не занят, и начинает им пользоваться.

Другие сообщения:

| Сообщение | От кого | Смысл |
|---|---|---|
| NAK | сервер | «этот адрес здесь недействителен», клиент начинает заново с DISCOVER |
| DECLINE | клиент | предложенный адрес уже кем-то занят (ответила проверка ARP) |
| RELEASE | клиент | клиент возвращает адрес |
| INFORM | клиент | клиент со статическим адресом просит только опции |

## Таймеры аренды

Адрес выдаётся в **аренду** на время (по умолчанию в RouterOS 7 это 30 минут, в старых значениях v6 10 минут; смотрите `lease-time`).

- На **T1 = 50%** аренды клиент **продлевает** её: unicast REQUEST к своему серверу.
- Если сервер не отвечает, на **T2 = 87,5%** он делает **rebind**: широковещательный REQUEST к любому серверу.
- На 100% аренда заканчивается, и клиент начинает с DISCOVER.

Короткая аренда быстрее переводит адреса между устройствами (кафе, гостевой Wi-Fi); длинная уменьшает трафик и переживает короткий отказ сервера.

## Идентификация клиента

Сервер узнаёт клиента по **идентификатору клиента** (опция 61) или, если клиент его не отправляет, по MAC-адресу. Опция 12 несёт имя хоста; RouterOS по умолчанию отправляет свою system identity.

# Lesson: DHCP-клиент в RouterOS

    /ip dhcp-client add interface=ether1 use-peer-dns=yes use-peer-ntp=yes add-default-route=yes

- **use-peer-dns**, **use-peer-ntp**: взять серверы DNS и NTP из ответа сервера.
- **add-default-route**: `yes` добавляет маршрут по умолчанию через полученный шлюз (с `default-route-distance`, по умолчанию 1), `no` не добавляет, а `special-classless` добавляет и маршруты из опции 121, и маршрут по умолчанию из опции 3.
- **dhcp-options**: какие опции отправляет клиент (по умолчанию hostname и clientid).
- **script**: выполняется при каждом событии bound и unbound, с переменными вроде `$bound`, `$"lease-address"` и `$"gateway-address"`. Типичное применение: изменить рекурсивный маршрут или правило NAT, когда провайдер меняет адрес.

Клиент запрашивает у сервера опции 1 (маска), 3 (маршрутизатор), 6 (DNS), 15 (домен), 33 (статические маршруты), 42 (NTP) и 121 (бесклассовые маршруты). Когда сервер отправляет опцию 121, стандартный клиент **игнорирует опцию 3**, поэтому сервер должен включить маршрут по умолчанию в саму опцию 121.

# Lesson: Сервер, сети и опции

DHCP-серверу в RouterOS нужны четыре вещи:

    /ip address add address=192.168.33.1/24 interface=bridgeLAN
    /ip pool add name=lan-pool ranges=192.168.33.10-192.168.33.254
    /ip dhcp-server add name=dhcp1 interface=bridgeLAN address-pool=lan-pool lease-time=1h
    /ip dhcp-server network add address=192.168.33.0/24 gateway=192.168.33.1 dns-server=192.168.33.1 domain=lab.local ntp-server=192.168.33.1

- **Один сервер на интерфейс** (или на relay). У интерфейса должен быть адрес в обслуживаемой сети.
- **Пул**: динамический диапазон. `next-pool` подключает следующий пул, когда этот заполнен. Статические аренды (`/ip dhcp-server lease make-static`) могут быть вне пула.
- **Network**: опции для клиентов этой подсети. Сервер выбирает запись network, в которую попадает выдаваемый адрес.

| Опция | Код | Поле в /ip dhcp-server network |
|---|---|---|
| маска подсети | 1 | netmask (берётся из address) |
| маршрутизатор (шлюз) | 3 | gateway |
| DNS-серверы | 6 | dns-server |
| имя домена | 15 | domain |
| NTP-серверы | 42 | ntp-server |
| WINS | 44 | wins-server |
| TFTP / загрузочный файл | 66 / 67 | next-server, boot-file-name |

## Свои опции

Всё остальное описывается в `/ip dhcp-server option` и подключается к сети:

    /ip dhcp-server option add name=tftp code=66 value="'10.0.0.5'"
    /ip dhcp-server network set [find address=192.168.33.0/24] dhcp-option=tftp

Значение это hex (`0x…`), строка в одинарных кавычках или адрес; несколько опций группируются в `/ip dhcp-server option sets` и подключаются через `dhcp-option-set`.

## Опция 121: бесклассовые статические маршруты

Опция 121 (RFC 3442) передаёт клиенту маршруты. Каждый маршрут кодируется так:

1. один байт: длина префикса;
2. только **значащие октеты** сети назначения (для /16 нужно 2, для /24 нужно 3, для /0 ни одного);
3. четыре байта: шлюз.

![Как 0x100A270A260101 раскодируется в 10.39.0.0/16 через 10.38.1.1](/img/mtctce/opt121.svg)

LAN с лабораторной сетью 10.10.0.0/16 за 192.168.33.254 и основным маршрутизатором 192.168.33.1:

    10.10.0.0/16 via 192.168.33.254  → 10 0A 0A C0 A8 21 FE
    0.0.0.0/0    via 192.168.33.1    → 00 C0 A8 21 01

    /ip dhcp-server option add name=classless code=121 value=0x100A0AC0A821FE00C0A82101
    /ip dhcp-server network set [find address=192.168.33.0/24] dhcp-option=classless

Пользуйтесь симулятором **кодирования опции 121**, а не считайте байты вручную. Windows понимает и старую опцию Microsoft 249 с тем же форматом.

# Lesson: Два сервера, authoritative и чужие серверы

## Основной и резервный

Два DHCP-сервера в одной LAN оставляют адреса доступными при отказе одного из них, но они не должны выдавать одни и те же адреса: дайте каждому свою часть диапазона. Чтобы один стал резервным, используйте **delay-threshold**:

    /ip dhcp-server set dhcp1 delay-threshold=5s

Клиент пишет в каждый DHCP-пакет (поле *secs*), сколько времени он уже пытается. Сервер с delay-threshold игнорирует запросы с меньшим значением secs. Пока основной сервер отвечает в первую секунду, резервный молчит; если основной недоступен, клиент продолжает попытки, и через 5 секунд отвечает резервный. На relay delay-threshold работает так же.

## authoritative

| Значение | Поведение |
|---|---|
| yes | сервер отвечает клиентам, для которых у него нет аренды: REQUEST на неизвестный адрес получает NAK, и клиент быстро начинает заново |
| no | запросы на неизвестные аренды игнорируются; клиент ждёт свой сервер |
| after-2sec-delay, after-10sec-delay | сервер ждёт столько, прежде чем забрать такого клиента |

`yes` правильно, когда сервер единственный, например после смены адресации: клиенты со старыми адресами сразу переходят на новые. При втором сервере в LAN `yes` на обоих заставит их отправлять NAK клиентам друг друга; резервный должен использовать `no` или значение с задержкой.

## Чужие DHCP-серверы

Домашний роутер, подключённый наоборот, или атакующий могут запустить второй DHCP-сервер в вашей LAN. Клиенты, принявшие его предложение, получают неверный шлюз и DNS: в лучшем случае без Интернета, в худшем man-in-the-middle. RouterOS обнаруживает чужие серверы:

    /ip dhcp-server alert add interface=bridgeLAN valid-server=00:0C:42:11:22:33 alert-timeout=1h on-alert=":log warning \"rogue DHCP server\""

- **valid-server**: MAC-адреса разрешённых серверов; собственный сервер маршрутизатора всегда разрешён.
- Когда на интерфейсе отвечает другой сервер, маршрутизатор пишет в лог «discovered unknown dhcp server» и выполняет **on-alert** (скрипт, например отправку письма).
- Обнаружение это не блокировка. Для блокировки нужен DHCP snooping с доверенными портами на коммутаторах (MTCSWE) или фильтры бриджа, отбрасывающие UDP 67 с недоверенных портов.

Лаба **резервный DHCP** настраивает роль резервного сервера и оповещение.

# Lesson: DHCP relay

DHCP DISCOVER это широковещательный пакет, а маршрутизаторы не пересылают broadcast. Поэтому филиалу или VLAN без своего сервера нужен **relay**: маршрутизатор, который принимает широковещательный запрос клиента и пересылает его unicast на сервер в другой сети.

![Relay пересылает broadcast клиента как unicast, а сервер выбирает пул по адресу relay](/img/mtctce/dhcp-relay.svg)

На relay:

    /ip dhcp-relay add name=to-hq interface=bridgeLAN dhcp-server=22.1.1.10 local-address=192.168.33.1 disabled=no

- **interface**: где находятся клиенты.
- **dhcp-server**: адрес сервера (можно указать несколько).
- **local-address**: адрес relay в сети клиентов. Он вписывается в пакет как *адрес шлюза* (giaddr), и сервер отвечает на него.
- **add-relay-info=yes** добавляет опцию 82 (relay agent information) с портом и relay, чтобы сервер различал клиентов на разных портах.
- На интерфейсе либо DHCP-сервер, либо relay, но не оба.

На сервере RouterOS сеть через relay это отдельный сервер, привязанный к адресу relay:

    /ip pool add name=branch33 ranges=192.168.33.10-192.168.33.254
    /ip dhcp-server add name=branch33 interface=ether1 relay=192.168.33.1 address-pool=branch33 disabled=no
    /ip dhcp-server network add address=192.168.33.0/24 gateway=192.168.33.1 dns-server=192.168.33.1

У сервера должен быть маршрут обратно в 192.168.33.0/24, а файрволы между ними должны пропускать UDP 67 в обе стороны. Лаба **DHCP relay** настраивает сторону филиала.
